# Git学習教材（VSCodeのGit UIだけで学ぶ実践編）

このドキュメントは、`git_training1` フォルダを教材にして、Gitの基本操作を
**ターミナル（コマンドライン）を使わず、VSCodeの画面操作だけ**で
「リポジトリ作成 → 変更 → Commit → Branch → Merge → GitHubへPublish/Push →
Fetch / Pullの違い」の順に覚えるためのものです。

## 使う場所（先に覚える3箇所）

1. **ソース管理パネル**：左側のアクティビティバーにある、枝分かれした線のようなアイコン
   （ショートカット：`Cmd+Shift+G` → もう一度 `G`）
2. **左下のステータスバー**：現在のブランチ名や、Push/Pull件数（雲/矢印アイコン）が表示される場所
3. **コマンドパレット**：`Cmd+Shift+P` で開く検索窓。メニューに出てこない細かい操作
   （ブランチのマージ・削除など）はここから `Git:` と入力して探します

---

## 0. 事前準備（初回のみ・エラーが出た場合だけ対応）

VSCodeには「Gitのユーザー名・メールアドレス設定」専用の画面がありません。
もしコミット時に「Please tell me who you are」といったエラーが表示された場合のみ、
その時初めてターミナルを一度だけ使う必要があります（それ以外は本教材はすべてUI操作です）。
このMacで過去に一度でもGitを使ったことがあれば、すでに設定済みで表示されません。

---

## Step 1. ローカルリポジトリを作る

1. VSCode左側の**ソース管理アイコン**をクリックして開く
2. 「**Initialize Repository**」（リポジトリを初期化）というボタンが表示されるのでクリック
3. しばらくすると、「変更点（Changes）」の欄に大量のファイルが一覧表示される
   → これがまだコミットされていない状態です

`.gitignore` はすでに用意されているため、`build/` や `.dart_tool/` などの
生成物は一覧に出てきません（エクスプローラーで中身を確認してみてもOKです）。

---

## Step 2. 最初のコミットをする

1. ソース管理パネル上部のメッセージ入力欄に
   `Initial commit: Flutterプロジェクトの初期状態` と入力する
2. 「変更点（Changes）」の見出しにマウスを乗せると出てくる **「+」アイコン**をクリックして
   全ファイルをステージング（コミット対象に追加）する
   → ファイル一覧が「ステージされている変更」欄に移動する
3. 入力欄の上にある**チェックマーク（✓ Commit）**をクリックする

これで最初のコミットが完了しました。ソース管理パネル上部の「グラフ」アイコン、
または画面下部の履歴表示で、コミットが1件記録されたことを確認できます。

---

## Step 3. ファイルを変更してコミットする練習

1. `README.md` を開き、末尾に以下を追記して保存（`Cmd+S`）する

```markdown
## 学習メモ
これはGitの練習用に編集した行です。
```

2. ソース管理パネルを見ると、`README.md` が「変更点」欄に **M**（Modified）マーク付きで表示される
3. `README.md` を**クリック**すると、変更前後を色分けした差分画面（diff）が開く
   （緑＝追加された行、赤＝削除された行）
4. `README.md` の右側の **「+」**をクリックしてステージングする
5. メッセージ欄に `README.mdに学習メモを追記` と入力し、チェックマークでコミットする

**ポイント**：
- 保存しただけ＝「変更点」（まだ記録されていない）
- 「+」でステージ＝「コミット候補」
- チェックマークでコミット＝「履歴に記録された」

```
変更点(Changes) --(+をクリック)--> ステージ済み --(✓Commitをクリック)--> 履歴
```

---

## Step 4. ブランチを作って変更する

1. **左下のステータスバー**にある現在のブランチ名（`main` など）をクリックする
2. 画面上部に候補一覧が出るので、「**+ Create new branch...**」を選ぶ
3. ブランチ名として `feature/change-title` と入力してEnter
   → 左下の表示が新しいブランチ名に変わる

`lib/main.dart` を開き、以下を書き換えて保存する。

- 13〜14行目付近
  ```dart
  title: 'Flutter Demo',
  ```
  ↓
  ```dart
  title: 'Git学習アプリ',
  ```

- 33行目付近
  ```dart
  home: const MyHomePage(title: 'Flutter Demo Home Page'),
  ```
  ↓
  ```dart
  home: const MyHomePage(title: 'Git学習 Home Page'),
  ```

ソース管理パネルで `lib/main.dart` をステージ（+）し、
`アプリタイトルをGit学習用に変更` とメッセージを入れてコミットする。

**ブランチの独立性を確認する**：
左下のブランチ名をクリックし、一覧から `main` を選んで切り替える。
`lib/main.dart` を開くと、タイトルが元の `Flutter Demo` に戻っているはずです。
これがブランチごとに履歴が独立しているということです。

---

## Step 5. マージする

1. 左下のブランチ名が `main` になっていることを確認する
2. `Cmd+Shift+P` でコマンドパレットを開き、`Git: Merge Branch...` と入力して選択
3. 一覧から `feature/change-title` を選ぶ

`lib/main.dart` を開き、タイトルが `Git学習アプリ` に変わっていれば成功です。

不要になったブランチは削除できます（任意）。
`Cmd+Shift+P` → `Git: Delete Branch...` → `feature/change-title` を選択。

### （応用）コンフリクトを体験してみる

余裕があれば、`main` と別ブランチで**同じ行**を別々の内容に変更してからマージすると
「コンフリクト（衝突）」が発生します。VSCodeのエディタ上に
`現在の変更を許可` / `入力側の変更を許可` / `両方の変更を許可` といったボタンが
インラインで表示されるので、好きな方を選ぶか手動編集して保存します。
保存後、ソース管理パネルでそのファイルを「+」でステージし、チェックマークでコミットすれば
コンフリクト解決の完了です。

---

## Step 6. GitHubへ公開する（Publish to GitHub）

VSCodeには「ボタン1つでGitHub上にリポジトリを新規作成してPushする」機能があります。
事前にGitHubでリポジトリを作る必要はありません。

1. ソース管理パネル上部（または左下）に表示されている
   「**Publish to GitHub**」ボタンをクリックする
2. 初回はGitHubへのサインインを求められるので、開いたブラウザ画面で認証・許可する
3. 「Publish to GitHub public repository」または
   「Publish to GitHub private repository」を選ぶ（練習用なら private がおすすめ）
4. リポジトリ名（例：`git_training1`）を確認してEnter

これだけで、GitHub上にリポジトリが作成され、`main` ブランチの全コミットが
自動でPushされます。ブラウザでGitHubのリポジトリページを開き、
`README.md` や `lib/main.dart` の内容が反映されていることを確認しましょう。

---

## Step 7. 追加の変更をPushする

1. 好きな部分をもう1箇所変更して保存する（例：`main.dart` のツールチップ文言を変更）
2. ソース管理パネルで「+」ステージ →メッセージ入力 →チェックマークでコミット
3. **左下のステータスバー**に、雲アイコンと「↑1」のような表示が出る
   （＝リモートより1コミット進んでいる、の意味）
4. その雲アイコン（**Sync Changes**）をクリックする

これでPushが完了します。GitHub側でも変更が反映されていることを確認しましょう。

---

## Step 8. Fetch を練習する

「Fetch」は「リモートの最新情報を確認するだけ（自分のファイルは変えない）」操作です。

1. ブラウザでGitHubのリポジトリページを開く
2. `README.md` を開き、鉛筆アイコン（Edit this file）をクリック
3. 適当な1行を追記する（例：`## GitHub側での更新テスト`）
4. 画面下部の「Commit changes...」で、**直接 main ブランチにコミット**する
   （＝「他の人がGitHub上で直接変更した」状態を再現）

VSCodeに戻り、`Cmd+Shift+P` → `Git: Fetch` を実行する。

- エディタ上の `README.md` の中身は**変わりません**
- 左下のステータスバーの矢印表示が「↓1」のように変わり、
  「リモートに新しいコミットがあるが、まだ取り込んでいない」ことがわかります

**つまりFetchは「情報だけ取ってきて、自分の作業内容には一切触らない」**操作です。
安全に最新状況を確認したいときに使います。

---

## Step 9. Pull を練習する

Fetchで確認した内容を、実際に自分の `main` に取り込みます。

1. `Cmd+Shift+P` → `Git: Pull` を実行する
   （または、ステータスバーの雲/矢印アイコン「**Sync Changes**」をクリックしてもOK。
   こちらはPullとPushを両方まとめて行います）
2. `README.md` を開くと、GitHub上で追記した行が反映されているのを確認する

---

## Fetch と Pull の違いまとめ

| | 何をするか | ローカルのファイルへの影響 |
|---|---|---|
| Fetch（`Git: Fetch`） | リモートの最新履歴を取得するだけ | 影響なし（ステータスバーの「↓件数」が増えるだけ） |
| Pull（`Git: Pull` / Sync Changes） | Fetch + リモートの内容を現在のブランチに取り込む（マージ） | ローカルのファイルに変更が反映される |

つまり、

```
Pull  =  Fetch  +  取り込み（マージ）
```

**実務では**、いきなりPullせず、まずFetchで「何が変わったか」を確認してから
取り込む、という使い方をすると事故が減ります。

## VSCode UI操作 早見表

| やりたいこと | 操作 |
|---|---|
| リポジトリ作成 | ソース管理パネル →「Initialize Repository」 |
| ステージング | 変更点ファイルにマウスオーバー →「+」 |
| コミット | メッセージ入力 → チェックマーク（✓） |
| 差分（diff）を見る | 変更点のファイル名をクリック |
| ブランチ作成・切替 | 左下のブランチ名をクリック →「+ Create new branch...」または一覧から選択 |
| マージ | `Cmd+Shift+P` →`Git: Merge Branch...` |
| ブランチ削除 | `Cmd+Shift+P` →`Git: Delete Branch...` |
| GitHubへ初回公開 | ソース管理パネル →「Publish to GitHub」 |
| 2回目以降のPush | 左下の雲アイコン（Sync Changes）またはコマンドパレット `Git: Push` |
| Fetch | `Cmd+Shift+P` →`Git: Fetch` |
| Pull | `Cmd+Shift+P` →`Git: Pull`、または雲アイコン（Sync Changes） |

---

## この教材の進め方まとめ

1. Step 1〜2：リポジトリ初期化 → 最初のコミット
2. Step 3：ファイル変更 → コミットの反復練習
3. Step 4〜5：ブランチ作成 → 変更 → マージ
4. Step 6〜7：GitHubへPublish → 追加コミットのPush
5. Step 8〜9：GitHub側で変更 → Fetchで確認 → Pullで取り込み

一通り終えたら、`lib/main.dart` の別の場所（ボタンのテキストや色など）を
変えてブランチ作成からもう一周してみると、UI操作が体に馴染みます。
